# AI講師 iOS 要件定義書

> 本書は iOS 版で**Web版と異なる点・追加する点だけ**を書く。共通の仕様（用語、講義の構造、
> AI の振る舞い、上限値など）は Web版の要件定義書を正とし、「Web §4.6」のように節番号で参照する。
> Web版：`https://github.com/pinshypinshy/ai-koushi` の `REQUIREMENTS.md`

---

## 1. 概要

### 1.1 目的
- AI講師の受講・確認テスト・誤答の復習を、スマートフォンのネイティブアプリで行えるようにする

### 1.2 Web版との役割分担
| 作業 | 主に使う環境 | 理由 |
|---|---|---|
| 講義の作成（教材の貼り付け） | Web版（PC） | 長い教材の貼り付けと確認は、大きな画面とキーボードが向いている |
| 受講・確認テスト・誤答の復習 | iOS版 | 短い空き時間に少しずつ進める使い方が中心になる |

### 1.3 前提
- サーバー・API・認証は Web版の本番環境をそのまま使う。iOS版のためにサーバーは変更しない
  （変更が必要になった場合は、その時点で個別に判断する）
- API の契約は Web版の `shared/api.ts` を正とする
- 用語は Web §2 に従う

## 2. スコープ

### 2.1 段階
| 段階 | 内容 |
|---|---|
| 1 | ゲストログイン＋サイドバー（講義一覧・利用状況・ログアウト）＋選択中の講義の概要 |
| 2 | 講義のストリーミング受講（講義本文・質問応答・ステップ完了） |
| 3 | 確認テスト・誤答の復習 |
| 4 | 設計判断の記録（ADR）の整備 |
| 5 | Googleログイン、講義作成、App Store 公開（実施するかは未定） |

### 2.2 段階1の範囲
**含む**：ゲストログイン、サイドバー（講義一覧・利用状況・ログアウト）、選択中の講義の概要、
空状態、セッション切れの扱い

**含まない**：
- Googleログイン（サーバー側の変更が必要になる見込みのため。段階5）
- 受講（メイン画面に講義本文を出すのは段階2）
- 講義の作成・削除・複製・名前の変更（Web版で行う）

## 3. 画面（段階1）

画面の骨格は「メイン画面＋左から開くサイドバー」とする。講義一覧はサイドバーに置き、
メイン画面にはサイドバーで選んだ講義を表示する（Web §3.4 のサイドバーと同じ構成）。

| ID | 画面 | 表示する条件 |
|---|---|---|
| iSC-01 | ログイン | 起動時に未ログイン／セッション切れ／ログアウト後 |
| iSC-02 | 選択中の講義 | ログイン済みで講義が1件以上 |
| iSC-03 | 空状態 | ログイン済みで講義が0件 |
| iA-1 | サイドバー | iSC-02・iSC-03 の左上のメニューボタンで開く |

### 3.1 iSC-01 ログイン
- ログインID・パスワードの入力欄と、ログインボタン
- パスワードは伏せ字で表示する
- エラーメッセージの表示領域
- ログインIDの欄で改行キーを押すとパスワードの欄へ移り、パスワードの欄で改行キーを押すとログインボタンを押したのと同じ動きになる
- 入力欄は iOS のパスワード自動入力に対応させる。ログインIDの欄では自動の大文字化と修正候補を切る
- 送信中は、ログインボタンの中に読み込み中の表示を出す

### 3.2 iSC-02 選択中の講義
- 左上にサイドバーを開くメニューボタンを置く
- 選択中の講義のタイトルと状態を表示する。状態の表示は 3.4 の講義一覧の行と同じ
- 受講の操作は置かない（段階2）

### 3.3 iSC-03 空状態
- 左上にサイドバーを開くメニューボタンを置く
- 講義がまだ無いことと、講義は Web版で作成することを案内する
- Web版を開くボタン（Safari で本番の URL を開く）

### 3.4 iA-1 サイドバー
上から順に次を置く。

1. **講義一覧**（`CourseSummary` の項目）

   | 講義の状態（`status`） | 表示 |
   |---|---|
   | `ready` | タイトル、進捗（`completedSteps` / `totalSteps`）。`totalSteps` が 0 のときは進捗を出さない |
   | `generating` | タイトル、「生成中」 |
   | `failed` | タイトル、「生成に失敗しました」 |

   - 並び順はサーバーが返した順のまま（並べ替えない）
   - 選択中の講義の行を強調する
   - 行を押すと、その講義を選択状態にしてサイドバーを閉じる
   - 下に引っ張ると一覧を取り直す（4.3）
   - 講義が0件のときは、一覧の代わりに「講義はまだありません」と表示する
2. **今月の利用状況**（`UsageSummary`。Web §3.4 A-5 と同じ表示）
   - 「AI利用額」：`costUsd / costLimitUsd` を割合（%）で示す帯。金額は表示しない
   - 「講義作成」：`courses / courseLimit` を「n / 上限 件」と帯で示す
   - 割合は四捨五入した整数で、100% を上限とする。上限が0以下のときは 0% とする
   - 2本のうち大きい方の割合が 80% 以上で「上限に近づいています。」、100% で
     「上限に達しました。新しい講義は作成できません。」を表示する（Web §8.2.4）
   - 帯の色は、それぞれの帯の割合で 80% 以上・100% の境界で切り替える
3. **ユーザー**（サイドバーの最下部。Web SC-15 と同じ）
   - 人のアイコンと表示名（`ApiUser.displayName`）を並べたボタンを置く
   - 押すとメニューを開き、表示名・メールアドレス（`ApiUser.email`）と「ログアウト」を出す。
     「ログアウト」を押すと 4.5 を行う

## 4. 振る舞い（段階1）

### 4.1 起動
1. `GET /api/bootstrap` を呼ぶ
2. 結果に応じて分岐する

| 結果 | 遷移 |
|---|---|
| 200 | 講義が1件以上なら iSC-02、0件なら iSC-03 |
| 401 | iSC-01 |
| 通信エラー・その他のエラー | エラーを表示し、再試行できるようにする |

**満たす条件**
- 前回ログインしたまま（Cookie の有効期限内）であれば、ログイン画面を経由せずにメイン画面が出る
- 読み込み中であることが分かる
- 起動直後に選択する講義は、一覧の先頭の講義とする

### 4.2 ゲストログイン（Web §4.6）
1. ログインIDとパスワードが両方入力されるまで、ログインボタンを押せない
2. `POST /auth/guest` に `{ loginId, password }` を送る
3. 結果に応じて分岐する

| 結果 | 振る舞い |
|---|---|
| 204 | `GET /api/bootstrap` を呼び、4.1 と同じくメイン画面へ |
| 400／401／429 | 応答の `message` をそのまま表示する。ログイン画面に留まる |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」を表示する |
| その他 | 「ログインできませんでした。時間をおいて再度お試しください。」を表示する |

**満たす条件**
- 送信中はボタンを押せない（二重送信しない）
- 失敗した後もログインIDは消えない。パスワードは空にする
- 前回のエラーメッセージ（4.4 のセッション切れの案内を含む）は、ログインボタンを押した時点で消す
- 本文の無い 400／401／429 は、表示する文言が無いため「その他」として扱う
- 401 と 429 の文言はサーバーが決める。iOS側で「IDが存在しない」と「パスワードが違う」を
  区別して表示しない（Web §4.6 の総当たり対策と揃える）

### 4.3 講義一覧の取り直し
- サイドバーの一覧を下に引っ張ったとき、`GET /api/bootstrap` を呼んで一覧と利用状況を置き換える
- 取り直した一覧に選択中の講義があれば選択を保つ。無ければ先頭の講義を選択する。
  0件になったら iSC-03 にする
- 失敗したときは、表示中の一覧を残したまま、一覧の一番上にエラーメッセージを出す。
  次に取り直しを始めた時点で消す

| 結果 | 振る舞い |
|---|---|
| 401 | 4.4 |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」を表示する |
| その他 | 「講義一覧を更新できませんでした。時間をおいて再度お試しください。」を表示する |

### 4.4 セッション切れ
- どの API で 401 を受けても、表示中の状態を破棄して iSC-01 へ戻す
- iSC-01 に「ログインの有効期限が切れました。もう一度ログインしてください。」を表示する

### 4.5 ログアウト
1. `POST /auth/logout` を呼ぶ
2. 成否にかかわらず、手元の Cookie を削除し、表示中の状態を破棄して iSC-01 へ戻す
   （通信に失敗しても、利用者から見てログアウトできないことは避けるため）

## 6. テストの観点（段階1）
TestStore で次を確かめる。API は Dependency を差し替え、本物を呼ばない。

1. 起動：200（講義あり）→ 選択中の講義（先頭）／200（0件）→ 空状態／401 → ログイン画面／通信エラー → エラー表示
2. ログイン：204 → メイン画面へ／401・429 → サーバーの文言を表示し、パスワードが空になる／通信エラー → 規定の文言を表示
3. ログイン：送信中に再度ボタンを押しても、2回目の送信が起きない
4. 取り直し：失敗しても表示中の一覧が残り、エラーメッセージが出る／次に取り直しを始めるとエラーメッセージが消える／選択中の講義が残っていれば選択を保つ
5. セッション切れ：401 を受けたらログイン画面へ戻り、案内文が出る
6. ログアウト：通信が失敗しても、ログイン画面へ戻る
7. 講義の選択：サイドバーで行を押すと、その講義が選択されサイドバーが閉じる
8. 利用状況：割合の計算（四捨五入・100% 上限・上限0以下）と、80%／100% の境界での注意文の切り替え

## 7. 決定事項

| 決定 | 理由 | 記録 |
|---|---|---|
| アーキテクチャは TCA | ストリーミングの状態遷移・途中キャンセル・遅れて届いたデータの扱いを、仕組みとして持てるため | `Docs/ADR/0001-adopt-tca.md` |
| ローカルパッケージでモジュールを分割する | 依存の向きをコンパイラに守らせるため | `Docs/ADR/0002-modularize-with-local-package.md` |
| Web版とは別リポジトリ | リリースの単位（App Store の審査／Cloudflare へのデプロイ）と開発ツールが異なるため | — |
| 段階1の認証はゲストログインのみ | 既存の Cookie によるセッションを、サーバーを変えずにそのまま使えるため | — |
| 講義一覧はサイドバーに置き、メイン画面には選択中の講義を表示する | Web版と同じ構成にし、起動してすぐ前回の講義に戻れるようにするため | — |
