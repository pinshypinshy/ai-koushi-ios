# 講義の会話を WKWebView と KaTeX で表示する

## ステータス

承認

## コンテキスト

- Markdown（見出し・リスト・表・コードブロック・引用・強調・リンク）と数式（LaTeX。文中の `$...$` と
  独立した行の `$$...$$`）の表示は必須である（Web §4.1.3）。講義の本文だけでなく、確認テストの
  問題文・選択肢・解説にも同じ規則を当てる
- 数式を書くのは、利用者が外部の生成AIに書き起こさせた教材（Web §4.8.2）と、それを読んだ講義の AI である。
  使われる LaTeX の命令に上限が無い
- Apple が提供しているのは Markdown の解析（`AttributedString(markdown:)`、swift-markdown）までで、
  ブロック要素の描画と数式の組版は提供していない
- 判断の基準は次の2つとする
  1. 確実に正しく表示すること
  2. コーディングの誤りを検知しやすい設計であること（このアプリのコードは大部分を AI が書く）

## 決定

- 講義画面の会話（発言の一覧・ステップの区切り・受信中の発言）を、1つの `WKWebView` で表示する
- Markdown と数式の処理は、Web版（`app/src/components/Markdown.tsx`）と同じ処理と設定
  （remark-gfm・remark-math・remark-cjk-friendly・rehype-katex、`\frac` を `\dfrac` に置き換える）をアプリに同梱し、
  通信せずに動かす
- WebView には表示だけをさせる。入力欄・ボタン・進捗パネル・エラー表示はネイティブ（SwiftUI）に置く
- 状態は Swift から JavaScript へ一方向に送る。JavaScript から Swift へ届けるのは、準備ができたこと・
  リンクが押されたこと・エラーの3つに限る
- 誤りを検知するため、次を備える
  - 送る内容は Swift の `Codable` の型と、TypeScript（strict）の型の両方で定義する
  - 「State の変化 → 送る内容」の計算は副作用の無い関数にし、Swift Testing で確かめる
  - シミュレータ上のテストで WebView に決まった Markdown を描かせ、KaTeX が Swift へ知らせた数式のエラーが0件であることと、
    描かれた数式の数が Markdown の中の数式の数と一致することを確かめる
  - JavaScript の例外と KaTeX のエラーを Swift へ知らせ、開発中のビルドではログに出す

## 検討した他の案

### 数式を記法のまま表示する（Markdown だけを自前で描画する）

- 採らなかった理由：数式の表示を必須とする Web §4.1.3 を満たさない

### MarkdownUI

- 採らなかった理由：文中の数式を表示できない。作者が開発を止めており、後継は Textual に移っている

### Textual

- 利点：Markdown のブロック要素と数式を1つのライブラリで表示でき、書く量が最も少ない
- 採らなかった理由：
  - 最低対応OSが iOS 18 で、このアプリの iOS 17 と合わない
  - 0.x で API が変わりうる。数式の部分（swiftui-math）は公開から日が浅く、実績が乏しい
  - 要件に合わなかったときに、中身に手を入れにくい

### Foundation の解析＋自前の描画＋SwiftMath

- 利点：描画以外を含め全体を Swift で書けるため、型の検査とテストで誤りを見つけやすい。iOS 17 で動く
- 採らなかった理由（SwiftMath のソースを読んで確かめた）：
  - 未対応の命令が1つでもあると、その数式全体が表示されない
  - `\text{}` の外にある ASCII 以外の文字と、プライム `'` を黙って読み飛ばす。数式を含む教材
    （263個）で調べると、16個がプライムを含んでいた。誤った数式がエラーにもテストの失敗にもならずに表示されるため、
    基準の1と2の両方に反する
  - `\overset`・`\underbrace`・`\tag`・`array` など、ライブラリを改造しない限り表示できない命令がある
  - 入力によってアプリが落ちる不具合が、最近まで修正され続けている。入力に上限が無いこのアプリでは避けにくい

### 発言ごとに WKWebView を置く

- 採らなかった理由：WebView は描き終わるまで高さが分からない。スクロール中や受信中に表示が跳ね、
  発言の数だけメモリも増える

## 結果（受け入れたコストを含む）

- Web版と同じ表示になる。未対応の命令があっても、その部分だけが赤い文字で表示され、アプリは落ちない
- 最低対応OSは iOS 17 のまま
- 外部ライブラリ（KaTeX と Markdown の処理）を同梱する。`CLAUDE.md` の「TCA 以外の外部ライブラリを追加しない」の例外になる
- TypeScript とビルドの道具がリポジトリに入り、言語が2つになる。境目の型は二重に定義することになり、
  その食い違いは型の検査では見つからないため、テストで見つける
- 不具合の調べ方が2つの言語にまたがる
- 色・文字の大きさ・ダークモードを CSS へ渡す必要がある
- 確認テスト（段階3）でも、数式の表示に同じ処理を使うことになる

- 2026-10-31：「決定」のテストの項目を直した。数式の描画の失敗を DOM の目印（`katex-error`）で見つけるとしていたが、
