# 新しい作業フォルダでブランチを切る

1つのフォルダで開けるブランチは1つだけである。同じフォルダで別のセッションが作業しているときに `git switch` をすると、そのセッションの作業フォルダまで切り替わる。そうなると、相手のコミットがこちらのブランチに乗り、こちらの未完成の変更が相手のフォルダに混ざる。worktree にすると、履歴は共有したまま、作業フォルダだけを分けられる。

スクリプトは `scripts/worktree.sh`（このファイルと同じフォルダからの相対パス）。どのフォルダで実行しても、元のフォルダ（最初に clone したフォルダ）を基準に動く。

## 手順

1. 同じフォルダを使っているセッションがあるかを確かめる（デスクトップアプリなら `list_sessions`。`cwd` がこのフォルダのもの）。あれば、`git switch` をせず、このスキルで進めると伝える
2. 作業の名前（英小文字・数字・ハイフン。例：`login-web-design`）と、元にするブランチ（既定はリポジトリの既定のブランチ）を決める。言われていなければ、作業の内容から案を出して確認する
3. `scripts/worktree.sh create <名前> [元のブランチ]` を実行する。`../<リポジトリ名>-<名前>` に、ブランチ `feature/<名前>` で worktree ができる。最後の行に新しいフォルダの絶対パスが出る
4. `scripts/worktree.sh candidates` で、リンクの候補（git の管理外で、ビルドの成果物ではないもの）を出す。一覧をユーザーに見せて、どれをリンクするかを選んでもらう。`CLAUDE.local.md` は、あれば最初から選んだ状態で見せる。候補が無ければこの手順と次の手順を飛ばす
5. `scripts/worktree.sh link <新しいフォルダ> <選んだパス>...` を実行する。リンクを張った後、どれも git に除外されていることを確かめる。除外されないものがあれば終了コード1で止まるので、その一覧をユーザーに伝え、リンクを消すか `.gitignore` を直すかを確認する
6. 新しいフォルダで、新しいセッションを確認せずに始める（`start_session`。`initiation: "user_asked"`、`context: "fresh"`、`cwd` は新しいフォルダ、`use_worktree: false`）。引き継ぎには、この会話で決まったこと・作業の範囲・終わりの条件を書く。セッションを始める手段が無い環境では、新しいフォルダの場所を伝えて終える

## 知っておくこと

- フォルダは丸ごとリンクしない。普通のフォルダを作り、中のファイルを1つずつリンクする（スクリプトがそうする）。`.gitignore` の `dir/` のように末尾が `/` の書き方は、フォルダにしか一致しない。git はフォルダへのリンクを1つのファイルとして扱うので、除外されずにコミットされうる
- そのため、元のフォルダの中に後から作ったファイルは、新しいフォルダには現れない。必要なら `link` をもう一度実行する（張ってあるリンクは飛ばす）
- リンクは絶対パスで張る。元のフォルダを移動するとリンクが切れる
- リンク先は実体が1つなので、2つのセッションが同じファイルに書き込む。編集の直前に読み直す
- Claude Code の記憶（auto memory）は、worktree でも元のリポジトリのものが読まれるので、リンクは要らない
