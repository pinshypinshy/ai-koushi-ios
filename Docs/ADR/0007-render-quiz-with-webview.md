# 確認テストの1問分を1つの WKWebView で表示する

## ステータス

承認

## コンテキスト

- 確認テストの問題文・選択肢・解説にも、Web §4.1.3 の Markdown と数式の規則が当たる
- ADR 0003 の決定は講義画面の会話についてのもので、WebView には表示だけをさせている
- 確認テストでは、数式を含む選択肢そのものを押して選ぶ

## 決定

- 問題文・選択肢・解説を、1つの `WKWebView` に描く。結果の画面の誤答の一覧も WebView に描く
- 選択肢に触れたら JavaScript から Swift へ知らせる。選択の状態は Reducer が持ち、Swift から WebView へ送り返す
- 「回答する」などのボタンはネイティブ（SwiftUI）に置く
- ADR 0003 は置き換えない。講義画面の会話は ADR 0003 のままとし、この ADR は確認テストの表示についての追加とする

## 検討した他の案

### 問題文・選択肢・解説の要素ごとに WKWebView を置く

- 採らなかった理由：1画面で最大6個になり、それぞれの高さが遅れて確定する

## 結果（受け入れたコストを含む）

- 数式の表示に、会話と同じ処理を使える
- WebView が1画面に1つで済む
- WebView の中の操作を Swift へ知らせる経路が増える
- 選択肢の見た目と押せる領域（`Docs/REQUIREMENTS.md` §3.7）を HTML と CSS で作ることになる
