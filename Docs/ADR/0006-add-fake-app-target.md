# 確認用のアプリを別のターゲットとして常設する

## ステータス

承認

## コンテキスト

画面を実機やシミュレータで確かめるときに、本物の API を呼ぶと料金がかかる。
そのため、確認のたびに `AIKoushiApp.swift` を偽の API に書き換え、確認後に元へ戻していた。
偽の API は今後も使うため、常設する。

## 決定

ビルドの時点で偽の API に固定する。そのために、アプリのターゲットを分ける。

- パッケージに `APIClientFake` を追加する。`APIClient` と `Models` に依存し、架空のデータだけを持つ
- Xcode プロジェクトに `AIKoushiFake` ターゲットを追加する。`AppFeature` と `APIClientFake` だけをリンクし、`APIClientLive` をリンクしない
- `AIKoushi` ターゲットは `APIClientFake` をリンクしない
- バンドル ID は `com.yuki-hiraishi.AIKoushi.Fake`、表示名は「AI講師 Fake」とし、アイコンを持たせない。本物のアプリと並べて入れ、見分けられるようにする
- `AIKoushi` と `AIKoushiFake` のスキームを共有する

## 検討した他の案

- **起動引数で切り替える**：同じアプリの起動時の引数で偽の API を使う。ビルドの時点で固定する案を選んだ
- **ビルド設定を増やして `#if` で切り替える**：コード上は両方の実装をリンクするため、`#if` を誤ると偽の版から本物の API を呼ぶおそれがある。独自の設定名を Swift Package Manager がどう扱うかの確認も要る

## 結果（受け入れたコストを含む）

- 確認用のアプリは本物の API を呼ぶコードを含まない。ADR 0002 の「本物の API を呼べない構造」と同じ考え方である
- 本物のアプリに偽の API が混ざらない
- `#if`、ビルド設定、起動引数は要らない
- ターゲットとアプリのファイルが1組増え、`project.pbxproj` の変更が増える
- `APIClientFake` にはテストを書かない。確認用の道具であり、動作は実行して確かめる
