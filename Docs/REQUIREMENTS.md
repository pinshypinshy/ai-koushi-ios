# AI講師 iOS 要件定義書

> 本書は iOS 版で**Web版と異なる点・追加する点だけ**を書く。共通の仕様（用語、講義の構造、
> AI の振る舞い、上限値など）は Web版の要件定義書を正とし、「Web §4.6」のように節番号で参照する。
> Web版：`https://github.com/pinshypinshy/ai-koushi` の `REQUIREMENTS.md`

---

## 1. 概要

### 1.1 目的
- AI講師の受講・確認テスト・誤答の復習を、スマートフォンのネイティブアプリで行えるようにする

### 1.2 Web版との役割分担
| 作業 | 主に使う環境 | 理由 |
|---|---|---|
| 講義の作成（教材の貼り付け） | Web版（PC） | 長い教材の貼り付けと確認は、大きな画面とキーボードが向いている |
| 受講・確認テスト・誤答の復習 | iOS版 | 短い空き時間に少しずつ進める使い方が中心になる |

### 1.3 前提
- サーバー・API・認証は Web版の本番環境をそのまま使う。iOS版のためにサーバーは変更しない
  （変更が必要になった場合は、その時点で個別に判断する）
- API の契約は Web版の `shared/api.ts` を正とする
- 用語は Web §2 に従う

## 2. スコープ

### 2.1 段階
| 段階 | 内容 |
|---|---|
| 1 | ゲストログイン＋サイドバー（講義一覧・利用状況・ログアウト）＋選択中の講義の概要 |
| 2 | 講義のストリーミング受講（講義本文・質問応答・ステップ完了） |
| 3 | 確認テスト・誤答の復習 |
| 4 | Googleログイン、講義作成、App Store 公開（実施するかは未定） |

### 2.2 段階1の範囲
**含む**：ゲストログイン、サイドバー（講義一覧・利用状況・ログアウト）、選択中の講義の概要、
空状態、セッション切れの扱い

**含まない**：
- Googleログイン（サーバー側の変更が必要になる見込みのため。段階4）
- 受講（メイン画面に講義本文を出すのは段階2）
- 講義の作成・削除・複製・名前の変更（Web版で行う）

### 2.3 段階2の範囲
**含む**：選択した講義の取得、講義本文の受信（③）、質問・応答（④）、ステップ完了（⑤）、進捗パネル、
全ステップ完了後の質問、Markdown・数式の表示、受信の失敗と中止の扱い、再生成、利用状況の更新

**含まない**：
- 確認テストと、確認テストへの導線（段階3）
- 教材の閲覧（Web §4.4 の教材タブ。iOS版では作らない）
- 完了済みのステップを押して、その時点の対話ログを読む操作（Web §4.2.3。会話は1本の時系列ですべて読めるため）

### 2.4 段階3の範囲
**含む**：タブバー、確認テストの開始画面、ステップの絞り込み、出題、正誤と解説、結果、復習モード、全ステップ完了後の「確認テストへ」ボタン

**含まない**：
- 確認テストの再生成（Web §4.3.5）
- 解答履歴の閲覧
- テストの途中経過の端末への保存

## 3. 画面

画面の骨格は「メイン画面＋左から開くサイドバー」とする。講義一覧はサイドバーに置き、
メイン画面にはサイドバーで選んだ講義を表示する（Web §3.4 のサイドバーと同じ構成）。
サイドバーはメイン画面の背面に置き、開くときはメイン画面を右へずらしてサイドバーを見せる
（X や Claude の iOS アプリと同じ形）。

| ID | 画面 | 表示する条件 |
|---|---|---|
| iSC-01 | ログイン | 起動時に未ログイン／セッション切れ／ログアウト後 |
| iSC-02 | 選択中の講義 | ログイン済みで講義が1件以上 |
| iSC-03 | 空状態 | ログイン済みで講義が0件 |
| iSC-04 | 確認テスト／開始 | タブバーで「確認テスト」を選び、テストを始めていないとき |
| iSC-05 | 確認テスト／出題 | テストの途中 |
| iSC-06 | 確認テスト／結果 | 全問に回答した後 |
| iA-1 | サイドバー | iSC-02・iSC-03 の左上のメニューボタン、またはメイン画面を右へスライドして開く |

### 3.1 iSC-01 ログイン
見た目と画面の文言は、Web版のログイン画面（Web版の `app/src/screens/Login.tsx`）に合わせる。
エラーメッセージは 4.2・4.4 のとおりとする。上から次の順に置き、全体を画面の縦方向の中央に置く。

1. アイコンと「AI講師」の見出し。その下に「参考書をアップロードすると、AIが講義と確認テストを作ります」
2. 「Googleでサインイン（未実装）」のボタン。段階4まで押せない
3. 「ゲストとしてサインイン」のボタン。押すと、このボタンの位置に入力枠が開く。入力枠を閉じる操作は無い
4. エラーメッセージの表示領域（入力枠の下）

入力枠には、上から案内文「発行された ID とパスワードを入力してください」、「ID」（ログインID）と
「パスワード」の入力欄、ログインボタン（文言は「サインイン」）を置く。
- パスワードは伏せ字で表示する
- ログインIDの欄で改行キーを押すとパスワードの欄へ移り、パスワードの欄で改行キーを押すとログインボタンを押したのと同じ動きになる
- 入力欄は iOS のパスワード自動入力に対応させる。ログインIDの欄では自動の大文字化と修正候補を切る
- 送信中は、ログインボタンの中に読み込み中の表示を出す

- iSC-01 を表示した時点では、入力枠は閉じている（起動時・セッション切れ・ログアウト後のいずれも）
- Web版には暗い配色が無いため、暗い配色は iOS版で決める

### 3.2 iSC-02 選択中の講義
- 一番上の行に、サイドバーを開くメニューボタンと、選択中の講義のタイトル（中央に置き、1行に収まらなければ末尾を省く）を置く
- 講義の状態（`status`）は、取得済みなら取得した講義のものを使う。一覧だけ先に `ready` になった講義を、ステップが無いまま受講の画面にしないため
- 状態が `ready` 以外のときは、状態だけを表示する。表示は 3.4 の講義一覧の行と同じ
- `ready` でもまだ取得できていないときは、4.6 の取得の表示だけを出す
- `ready` で取得済みのときは、画面の下端にタブバー（3.5）を置き、「講義」のタブには上から次を置く

1. **進捗パネル**（Web §4.2.3 の C-1 をモバイル向けにしたもの。Web SC-M01・SC-M02）
   - 折りたたんだ状態では1行で「ステップ n / 全体の数・現在のステップのタイトル」を表示する。
     全ステップ完了後は「全ステップ完了」と表示する
   - 押すと全ステップの一覧を展開し、会話を押し下げる。一覧が高くなりすぎるときは、一覧の中でスクロールする。完了したステップはチェックの印、現在のステップは強調、
     未着手のステップは淡い色で表示し、「k / 全体の数 ステップ完了」を添える。もう一度押すと閉じる
   - ステップのタイトルは文字のまま表示する（数式として組まない。Web版の区切りの表示と同じ）
2. **会話**（WebView で表示する。`Docs/ADR/0003-render-conversation-with-webview-katex.md`）
   - 発言を時系列に並べる。AI の発言は左寄せで Markdown・数式として表示し、利用者の発言は右寄せで文字のまま表示する
   - 各ステップの最初の発言（受信中の発言を含む）の前に、「ステップ n・タイトル」の区切りを入れる
   - Markdown と数式の規則は Web §4.1.3 と同じ。文中の分数は独立した行の数式と同じ大きさで組む（`\frac` を `\dfrac` として扱う）。
     生の HTML は HTML として扱わず、文字のまま表示する
   - 画像は外部から読み込まず、代わりの文字（画像の説明）を表示する（アプリが利用者の操作なしに通信しないようにするため）
   - 画面幅に収まらない数式・表・コードブロックは、それぞれの枠の中で横にスクロールさせ、会話全体は横にスクロールさせない
   - 受信中の発言は、届いた文字から順に表示する。まだ1文字も届いていなければ「応答を待っています」と表示する
   - 生成が途中で失敗した AI の発言（`interrupted`）の下に「応答が途中で途切れました」と表示する
   - 現在のステップの最後の発言が回答の無い質問で、4.13 の再生成ができるときは、その下に「応答を取得できませんでした」と表示する
   - 再生成の受信中は、置き換える発言を隠す（受信中の発言と同じ内容が二重に並ぶため）
   - 講義を開いたとき、利用者が発言を送ったときは末尾を表示する。新しい文字が届いたときは、末尾を表示している場合だけ末尾へ追従する
     （上へ戻って読んでいる最中に引き戻さないため）
   - リンクを押すと、利用者が既定に設定しているブラウザで開く。`http`・`https` 以外のリンクは、押しても何もしない
3. **操作の領域**（会話と入力欄の間）。次のうち、条件に合うものを上から順にすべて表示する
   - 受信の失敗を表示している間で、会話の中に再生成の対象（途切れた発言・回答の無い質問）が無いとき：エラーメッセージ（4.9）。
     発言の無いステップで失敗したとき、講義単位の上限に達したときなどが当たる。対象が会話にあるときは、2 の文言と重ならないよう出さない
   - 4.13 の再生成ができるとき：「再生成する」ボタン
   - 全ステップ完了後：「全ステップが完了しました」と「まだわからないことがあれば、いつでも質問してください」と「確認テストへ」ボタン（4.14）
   - 受信中でなく、現在のステップに発言が1件以上あるとき：「次のステップへ進む」ボタン（最後のステップでは「講義を終える」）。
     受信の失敗を表示している間も出す（失敗が続いても先へ進めるようにするため）。
     ステップの完了を待つ間は「要約を作成しています」と表示して押せなくする。講義の取得中（4.6）と読み直しの間（4.9・4.11）も押せなくする。
     失敗したときはボタンの下にエラーメッセージを出す（4.11）
4. **入力欄**（タブバーの上。キーボードが出ている間はキーボードの上）
   - 複数行の入力欄と送信ボタンを置く。改行キーは改行を入れる（日本語の変換の確定と区別できないため、送信は送信ボタンだけで行う）
   - 入力欄が空のときは「プロンプトを入力」と表示する
   - 前後の空白を除いて空のとき、受信中、ステップの完了を待つ間、講義の取得中（4.6）、読み直しの間（4.9・4.11）は、送信ボタンを押せない
   - キーボードは、会話を下へスクロールしたとき、サイドバーを開いたとき、入力欄・送信ボタン・タイトル以外を押したときに閉じる。押した場所の操作（リンクを開くなど）はそのまま行う。
     発言を送っても閉じない（続けて質問できるようにするため）

### 3.3 iSC-03 空状態
- 左上にサイドバーを開くメニューボタンを置く
- 講義がまだ無いことと、講義は Web版で作成することを案内する
  - 見出し：「まだ講義がありません」（Web SC-02 と同じ）
  - 説明：「講義は Web版で作成できます。作成した講義は、サイドバーの一覧を下に引っ張ると表示されます。」
- 「Web版を開く」ボタン（利用者が既定に設定しているブラウザで本番の URL を開く）

### 3.4 iA-1 サイドバー
開閉は次のとおり。どの操作でも、メイン画面が動くアニメーションで開き、閉じる。

- メイン画面のどこからでも右へスライドすると、指に合わせてメイン画面がずれ、サイドバーが見えてくる
- ただし、横にスクロールする枠（数式・表・コードブロック）をまだ右へ戻せるときは、その枠の上で始めた右へのスライドではサイドバーを開かない（枠を読み戻す操作とぶつかるため）。
  判定はスライドを始めた時点で行い、同じスライドで枠が左端まで戻っても開かない
- 開いている間は、右端にメイン画面の一部を残し、角を丸める。メイン画面は暗くしない
- 開いている間に左へスライドすると、指に合わせて閉じていく
- 指を離したとき、一定以上の速さで払っていれば払った向きに従う。そうでなければ、半分以上ずれていれば開き、
  そうでなければ閉じる。どちらも素早く収める
- 右端に残したメイン画面を押すと、選択を変えずに閉じる
- 開閉が確定したら、軽い振動を返す

上から順に次を置く。

1. **見出し**：「AI講師」（スクロールせず、常に一番上に表示する）
2. **講義一覧**（`CourseSummary` の項目）

   | 講義の状態（`status`） | 表示 |
   |---|---|
   | `ready` | タイトル、進捗（`completedSteps` / `totalSteps`）。`totalSteps` が 0 のときは進捗を出さない |
   | `generating` | タイトル、「生成中」 |
   | `failed` | タイトル、「生成に失敗しました」 |

   - 並び順はサーバーが返した順のまま（並べ替えない）
   - 行と行の間に区切り線を出さない。選択中の講義の行は、角を丸めた背景で強調する
   - 行を押すと、その講義を選択状態にしてサイドバーを閉じる
   - 下に引っ張ると一覧を取り直す（4.3）
   - 講義が0件のときは、一覧の代わりに「講義はまだありません」と表示する
3. **今月の利用状況**（`UsageSummary`。Web §3.4 A-5 と同じ表示）
   - 「AI利用額」：`costUsd / costLimitUsd` を割合（%）で示す帯。金額は表示しない
   - 「講義作成」：`courses / courseLimit` を「n / 上限 件」と帯で示す
   - 割合は四捨五入した整数で、100% を上限とする。上限が0以下のときは 0% とする
   - 2本のうち大きい方の割合が 80% 以上で「上限に近づいています。」、100% で
     「上限に達しました。新しい講義は作成できません。」を表示する（Web §8.2.4）
   - 帯の色は、それぞれの帯の割合で 80% 以上・100% の境界で切り替える
4. **ユーザー**（サイドバーの最下部。Web SC-15 と同じ）
   - 人のアイコンと表示名（`ApiUser.displayName`）を並べたボタンを置く
   - 押すとメニューを開き、表示名・メールアドレス（`ApiUser.email`）と「ログアウト」を出す。
     「ログアウト」を押すと 4.5 を行う

### 3.5 タブバー
- 「講義」と「確認テスト」の2つのタブを置く
- 講義の状態が `ready` で、講義を取得済みのときだけ表示する。それ以外のときは 3.2・3.3 のとおり表示し、タブバーを出さない
- 一番上の行（メニューボタンと講義のタイトル）は、どちらのタブでも表示する
- 確認テストのタブには、進捗パネル・操作の領域・入力欄を出さない（Web §3.4）

### 3.6 iSC-04 確認テスト／開始
上から次を置く。

1. **出題数と正答率**
   - 出題数：絞り込みで選ばれる設問の数を「n 問」と表示する
   - 正答率：講義全体で、解答したことのある設問のうち、最新の解答が正解である割合（四捨五入した整数）と「（正解の数 / 解答済みの数）」。解答済みが0件のときは「—」
2. **「テストを始める」ボタン**。出題数が0のときは押せない
3. **ステップの絞り込み**（見出し：「ステップで絞り込む（任意）」）
   - ステップごとに、タイトルと選択の印、「n問」を表示する。そのステップの設問に解答済みのものがあれば「/ 正答率 n%」を添える
   - 複数選べる。何も選ばないときは全問を、選んだときは選んだステップのどれかに関連する設問を出題する
   - 「設問はステップに1対1で対応しません。複数ステップにまたがる横断設問があるため、各行の合計は総問数と一致しないことがあります。」と添える
4. **「誤答のみに取り組む（n問）」ボタン**。対象が0問のときは押せないため、Web SC-12 は作らない

講義の確認テストの状態（`quizStatus`）が `ready` 以外のときは、上の代わりに次を表示する。

| `quizStatus` | 表示 |
|---|---|
| `failed` | 「確認テストの生成に失敗しました」「講義はそのまま受講できます。」 |
| `pending` | 「確認テストを作成しています。サイドバーの一覧を下に引っ張ると更新されます。」 |

### 3.7 iSC-05 確認テスト／出題
問題文・選択肢・解説は1つの WebView で表示する（`Docs/ADR/0007-render-quiz-with-webview.md`）。Markdown と数式の規則は、3.2 の会話と同じとする。
回答した後は、解説の先頭まで自動で移動する（問題文と選択肢が長いと、解説が画面の外に出て気づかないため）。上から次を置く。

1. **進み具合**：「第 n 問 / 全 m 問」と帯。復習モードでは「復習モード」と添える
2. **問題文**
3. **選択肢**：A〜D の印を付けて縦に並べる。省略せず全文を表示し、押せる領域の高さを 44pt 以上にする
4. **正誤と解説**（回答した後だけ）
   - 正解の選択肢に「正解」、誤って選んだ選択肢に「あなたの回答」を示す
   - 解説と、関連するステップのタイトルを表示する。関連するステップが複数あれば「（横断設問）」と添える
5. **ボタン**
   - 回答する前：「回答する」。選択肢を選ぶまで押せない。採点中は「採点しています」と表示して押せない
   - 回答した後：「次の問題へ」（最後の問題では「結果を見る」）
6. **「テストをやめる」ボタン**。押すと iSC-04 へ戻る。解答済みの記録は残る。採点中は押せない

### 3.8 iSC-06 確認テスト／結果
上から次を置く。

1. 「テスト終了」（復習モードでは「復習モード終了」）、正解の数 / 問題の数、正答率（四捨五入した整数）
2. 「誤答した問題」の一覧。今回のテストで間違えた問題の問題文を、数式として表示する。誤答が無ければ出さない。
   Web §3.2 の SC-11 とは異なり、行を押しても解説を再表示しない（Web版の実装に揃える）
3. ボタン
   - 「誤答のみ再挑戦（n問）」：n は講義全体で最新の解答が誤答である設問の数。0問のときは押せない
   - 「テスト一覧へ戻る」：iSC-04 へ戻る
   - 「講義へ戻る」：「講義」のタブを表示する。結果の画面は残し、「テスト一覧へ戻る」か再挑戦を選ぶまで消さない

## 4. 振る舞い

### 4.1 起動
1. `GET /api/bootstrap` を呼ぶ
2. 結果に応じて分岐する

| 結果 | 遷移 |
|---|---|
| 200 | 講義が1件以上なら iSC-02、0件なら iSC-03 |
| 401 | iSC-01（案内文は出さない。初めての起動やログアウト後と、期限切れを区別できないため） |
| 通信エラー | 見出し「読み込めませんでした」、説明「通信できませんでした。ネットワーク接続を確認してください。」、「再試行」ボタンを表示する |
| その他 | 見出し「読み込めませんでした」、説明「時間をおいて再度お試しください。」、「再試行」ボタンを表示する |

**満たす条件**
- 前回ログインしたまま（Cookie の有効期限内）であれば、ログイン画面を経由せずにメイン画面が出る
- 読み込み中であることが分かる
- 起動直後に選択する講義は、一覧の先頭の講義とする

### 4.2 ゲストログイン（Web §4.6）
1. ログインIDとパスワードが両方入力されるまで、ログインボタンを押せない
2. `POST /auth/guest` に `{ loginId, password }` を送る
3. 結果に応じて分岐する

| 結果 | 振る舞い |
|---|---|
| 204 | `GET /api/bootstrap` を呼び、4.1 と同じく分岐する（200 ならメイン画面、401 なら iSC-01 を出し直し、それ以外は 4.1 のエラー表示） |
| 400／401／429 | 応答の `message` をそのまま表示する。ログイン画面に留まる |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」を表示する |
| その他 | 「ログインできませんでした。時間をおいて再度お試しください。」を表示する |

**満たす条件**
- 送信中はボタンを押せない（二重送信しない）
- 失敗した後もログインIDは消えない。パスワードは空にする
- 前回のエラーメッセージ（4.4 のセッション切れの案内を含む）は、ログインボタンを押した時点で消す
- 本文の無い 400／401／429 は、表示する文言が無いため「その他」として扱う
- 401 と 429 の文言はサーバーが決める。iOS側で「IDが存在しない」と「パスワードが違う」を
  区別して表示しない（Web §4.6 の総当たり対策と揃える）

### 4.3 講義一覧の取り直し
- サイドバーの一覧を下に引っ張ったとき、`GET /api/bootstrap` を呼んで一覧と利用状況を置き換える
- 取り直した一覧に選択中の講義があれば選択を保つ。無ければ先頭の講義を選択する。
  0件になったら iSC-03 にする
- 失敗したときは、表示中の一覧を残したまま、一覧の一番上にエラーメッセージを出す。
  次に取り直しを始めた時点で消す

| 結果 | 振る舞い |
|---|---|
| 401 | 4.4 |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」を表示する |
| その他 | 「講義一覧を更新できませんでした。時間をおいて再度お試しください。」を表示する |

### 4.4 セッション切れ
- メイン画面を表示した後に API で 401 を受けたら、表示中の状態を破棄して iSC-01 へ戻す
  （4.1 の起動時と、4.2 のログイン直後の bootstrap は除く）
- iSC-01 に「ログインの有効期限が切れました。もう一度ログインしてください。」を表示する

### 4.5 ログアウト
1. `POST /auth/logout` を呼ぶ
2. 成否にかかわらず、手元の Cookie を削除し、表示中の状態を破棄して iSC-01 へ戻す
   （通信に失敗しても、利用者から見てログアウトできないことは避けるため）
- 応答を待つ間は「ログアウトしています」と読み込み中の表示を出す。先に iSC-01 へ戻すと、
  待っている間にログインし直したときの Cookie まで削除されるため

### 4.6 講義の取得
- 起動直後の講義は、`GET /api/bootstrap` の `selected` をそのまま使う（取り直さない）
- サイドバーで講義を選んだとき、および 4.3 の取り直しで選択中の講義が変わったときは、`GET /api/courses/:id` で取得する。
  同じ講義を選び直したときは取得しない
- ただし、選んだ講義が受信中、ステップの完了を待つ間、読み直しの間（4.10 で続いている場合）は取得しない
  （取得した内容で、受信中の発言や待っている結果を上書きしないため）
- 4.3 の取り直しで選択中の講義が変わらなくても、一覧の状態（`status`）が表示中の講義の状態と異なるときは取得する
  （生成中だった講義が受講できるようになった場合など）
- 取得中は、iSC-02 の一番上の行の下に読み込み中の表示を出す

| 結果 | 振る舞い |
|---|---|
| 200 | 3.2 のとおり表示する。条件を満たせば 4.7 を始める |
| 401 | 4.4 |
| 404 | 「講義が見つかりませんでした。サイドバーの一覧を下に引っ張って更新してください。」を表示する |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」と「再試行」ボタンを表示する |
| その他 | 「講義を読み込めませんでした。時間をおいて再度お試しください。」と「再試行」ボタンを表示する |

- 取得できたら、サイドバーの一覧の該当する行も、取得した講義の内容で置き換える（行と本体の内容を食い違わせないため）
- すでに会話を表示している講義で取得が失敗したときは、会話を残したまま、上の表の表示を一番上の行の下に出す。次に取得を始めた時点で消す
- 取得中は、送信ボタン・「再生成する」・「次のステップへ進む」を押せない（取得した内容で、新しく始めた受信や完了の結果を上書きしないため）

### 4.7 講義本文の受信（③、Web §4.2.2）
1. 次のすべてを満たすとき、`POST /api/courses/:id/lecture` を自動で呼ぶ
   - 講義の状態が `ready` で、全ステップが完了していない
   - 現在のステップに発言が1件も無い
   - 受信中でなく、受信の失敗（4.9）を表示していない
2. 応答は NDJSON で届く（`LectureStreamLine`）。`delta` は届いた順に受信中の発言へ足し、`done` で受け取った発言を会話に確定する
3. 確定したら 4.12 を行う

**満たす条件**
- 同じステップに対して、自動では1回しか呼ばない（呼ぶたびに AI の料金がかかるため）

### 4.8 質問・応答の送信（④、Web §4.2.4）
1. 送信ボタンを押すと、入力した文を会話にすぐ表示し、入力欄を空にする
2. `POST /api/courses/:id/messages` に `{ text }`（前後の空白を除いたもの）を送る
3. 応答の受け取りは 4.7 の 2・3 と同じ

**満たす条件**
- 全ステップ完了後も送信できる（Web §4.2.4、Q-32）
- 会話にすぐ表示した発言は、講義を取り直した時点でサーバーが保存したものに置き換わる

### 4.9 受信の失敗
| 結果 | 表示するメッセージ |
|---|---|
| 401 | 4.4 |
| 403 | 応答の `message` をそのまま表示する（この講義の生成量の上限に達した場合） |
| 通信エラー（応答が15秒途切れた場合を含む） | 「通信できませんでした。ネットワーク接続を確認してください。」 |
| `error` 行を受け取った／`done` を受け取る前に応答が終わった | 「応答が途中で止まりました。」 |
| その他 | 「応答を取得できませんでした。時間をおいて再度お試しください。」 |

- 401 以外では、失敗した後に `GET /api/courses/:id` で講義を取り直して会話を置き換え、4.12 を行う。
  途中まで生成された発言と送信した発言は、サーバーが保存している場合があるため（Web §5.7）
- 読み直しできたら、サイドバーの一覧の該当する行も、読み直した講義の内容で置き換える（4.6 と同じ）
- 途中まで届いた文字は、読み直しが終わるまで表示を残す
- 読み直しが失敗したときは、401 なら 4.4。それ以外は表示中の会話とエラーメッセージをそのまま残し、メッセージを足さない。
  途中まで届いた文字は、途切れた発言（`interrupted`）として手元の会話に残す
- 読み直しの間は、送信ボタン・「再生成する」・「次のステップへ進む」を押せない（読み直した内容で、新しく始めた受信や完了の結果を上書きしないため）
- `error` 行の `message` は表示しない（サーバー内部のエラー文であり、利用者向けの文言ではないため）
- エラーメッセージは、次に受信を始めた時点と、ステップ完了の 200 を受けた時点で消す（消さないと 4.7 の条件を満たせず、次のステップの本文が始まらないため）

### 4.10 講義の切り替えと受信の中止
- 受信中・ステップの完了を待つ間に別の講義を選んでも、受信と待機は続ける。届いた文字や結果はその講義にだけ反映し、
  戻るとその続きや結果を表示する（受信をやめてもサーバーが生成を止める保証は無く、戻ったときに同じ応答を二重に生成するおそれがあるため）
- 別の講義を選んでいる間にステップの完了を受けたときも、条件を満たせばその講義の 4.7 を始める
- 講義ごとの表示の状態（会話・受信中の発言・エラーメッセージ・入力欄の文字など）は、ログアウトするまで残す
- 4.3 の取り直しで一覧から消えた講義は、その講義の状態を捨て、受信もやめる
- ログアウトしたとき、セッションが切れたときは、すべての受信をやめる。やめた後に届いた文字は、どの講義にも反映しない

### 4.11 ステップ完了（⑤、Web §4.2.2）
1. 「次のステップへ進む」（最後のステップでは「講義を終える」）を押すと、
   `POST /api/courses/:id/steps/:stepId/complete` を呼ぶ
2. 200 で返った講義に置き換える。サイドバーの一覧の該当する行も、返った講義の内容で置き換える。次のステップがあれば 4.7 が始まる
3. 4.12 を行う

| 結果 | 振る舞い |
|---|---|
| 200 | 上の 2・3 |
| 401 | 4.4 |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」を表示し、4.12 を行う |
| その他（409 を含む） | 「ステップを完了できませんでした。時間をおいて再度お試しください。」を表示し、講義を取り直し、4.12 を行う |

**満たす条件**
- 完了を待つ間はボタンを押せない（二重送信しない）
- エラーメッセージは、ボタンをもう一度押した時点で消す
- 取り直しの間の操作と、取り直しの結果の扱いは、4.9 の読み直しと同じ

### 4.12 利用状況の更新
- 講義本文・質問応答・再生成の受信が終わったときと、ステップの完了を試みた後に、成功・失敗とも
  `GET /api/usage` を呼んでサイドバーの利用状況を置き換える（AI の料金は失敗しても発生するため）
- 401 を受けて 4.4 へ進むときは呼ばない
- 401 なら 4.4。それ以外の失敗では、表示中の利用状況をそのまま残し、メッセージは出さない

### 4.13 再生成（Web §5.7、Q-33）
1. 「再生成する」を押すと、`POST /api/courses/:id/regenerate` を呼ぶ。何をやり直すかはサーバーが決める
2. 応答の受け取りは 4.7 の 2・3 と同じ。ただし再生成で隠した発言があれば、末尾に足さずに `done` の発言で置き換える
   （手元に残した途切れた発言は、ID がサーバーの発言と異なるため、ID では対応づけない）

再生成ができるのは、次のすべてを満たすとき。全ステップ完了後の「現在のステップ」は最後のステップとする
- 受信中でなく、ステップの完了を待つ間でなく、講義の取得中でなく、読み直しの間でない
- 次のどちらかに当てはまる
  - 現在のステップの最後の発言が、回答の無い質問、または途中で途切れた発言（`interrupted`）
  - 現在のステップに発言が無く、受信の失敗を表示している
- 全ステップ完了後は、質問への回答のやり直しに限る（最後の発言が回答の無い質問か、途切れた発言の直前が質問のとき）。
  講義本文の生成はサーバーが受け付けないため（Web Q-32）

### 4.14 タブの切り替え
- 表示中のタブは講義ごとに覚える。初めて開く講義では「講義」を表示する
- タブバーを出さない講義（3.5）では、覚えているタブにかかわらず 3.2 の表示にする
- 「確認テストへ」を押すと「確認テスト」のタブを表示する
- 確認テストのタブを表示している間も、講義本文・質問応答の受信とステップの完了の待機は続ける（4.10 と同じ）

### 4.15 確認テストの取得
`GET /api/courses/:id/quiz` を呼ぶ。`quizStatus` が `ready` で、iSC-04 を表示するとき（テストの途中と結果の画面では呼ばない）に、次のいずれかで呼ぶ。
Web版で解いた結果を反映するため、開くたびに取り直す。

- 「確認テスト」のタブを開いたとき
- 「テストをやめる」「テスト一覧へ戻る」で iSC-04 へ戻ったとき
- 「確認テスト」のタブを表示している講義へ切り替えたとき
- 4.3 の取り直しで、表示中の講義の `quizStatus` が `ready` に変わったとき
- 「再試行」を押したとき

まだ取得できていないときは「確認テストを読み込んでいます」と表示する。取得済みのときは、取り直す間も iSC-04 を表示し、操作もできる。

| 結果 | 振る舞い |
|---|---|
| 200 | 設問と、設問ごとの最新の解答を置き換える |
| 401 | 4.4 |
| 404 | 「講義が見つかりませんでした。サイドバーの一覧を下に引っ張って更新してください。」を表示する |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」と「再試行」ボタンを表示する |
| その他 | 「確認テストを読み込めませんでした。時間をおいて再度お試しください。」と「再試行」ボタンを表示する |

- 取得済みの講義で失敗したときは、表示を残したまま、上の表の表示を iSC-04 の一番上に出す。次に取得を始めた時点で消す
- 「テストを始める」「誤答のみに取り組む」を押したら、取り直しをやめる（届いた古い解答で、新しい解答を上書きしないため）

### 4.16 出題
- 「テストを始める」は、絞り込みで選ばれる設問を出題する（3.6）
- 「誤答のみに取り組む」「誤答のみ再挑戦」（復習モード）は、最新の解答が誤答である設問を出題する。回答の仕方は通常と同じ（Web §4.3.4）
- 出題順は、始めるたびにシャッフルする（Web Q-6）。選択肢の順はサーバーが返した順のまま
- 新しい問題を出すときは、問題の先頭を表示する

### 4.17 解答
1. 選択肢を押すと、その選択肢を選ぶ。回答する前なら選び直せる
2. 「回答する」を押すと、`POST /api/questions/:id/attempts` に `{ selectedChoiceId }` を送る
3. 200 で正誤と解説を表示し、その設問の最新の解答を更新する。確定後は選び直せない（Web §4.3.2）
4. 「次の問題へ」で次の問題へ進む。最後の問題では iSC-06 を表示する

| 結果 | 振る舞い |
|---|---|
| 200 | 上の 3 |
| 401 | 4.4 |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」を表示する。選択を残し、もう一度押せる |
| その他（400・404 を含む） | 「採点できませんでした。時間をおいて再度お試しください。」を表示する。選択を残し、もう一度押せる |

**満たす条件**
- 採点中はボタンを押せない（二重送信しない）
- エラーメッセージは、「回答する」をもう一度押した時点で消す
- 確認テストの API は AI を呼ばないため、4.12 を行わない

### 4.18 テストの途中経過
- 開始画面の絞り込み、テストの途中経過（出題順・現在の問題・選択・正誤）、結果の画面は、4.10 の講義ごとの表示の状態に含める。
  タブや講義を切り替えて戻ると続きを表示する（Web版とは異なる。短い空き時間に少しずつ進める使い方のため。1.2）
- 採点中に別の講義を選んでも待機を続け、結果はその講義にだけ反映する
- 一覧から消えた講義の途中経過は捨てる。ログアウトしたとき、セッションが切れたときは、すべての途中経過を捨てて採点の待機をやめる
- 途中経過は端末に保存しない。アプリが終了すると消え、次に開いたときは iSC-04 を表示する。解答済みの記録はサーバーに残る

## 6. テストの観点
TestStore で次を確かめる。API は Dependency を差し替え、本物を呼ばない。

### 6.1 段階1

1. 起動：200（講義あり）→ 選択中の講義（先頭）／200（0件）→ 空状態／401 → ログイン画面／通信エラー → エラー表示
2. ログイン：204 → メイン画面へ／401・429 → サーバーの文言を表示し、パスワードが空になる／通信エラー → 規定の文言を表示
3. ログイン：送信中に再度ボタンを押しても、2回目の送信が起きない
4. ログイン：「ゲストとしてサインイン」を押すと入力枠が開く
5. 取り直し：失敗しても表示中の一覧が残り、エラーメッセージが出る／次に取り直しを始めるとエラーメッセージが消える／選択中の講義が残っていれば選択を保つ
6. セッション切れ：401 を受けたらログイン画面へ戻り、案内文が出る
7. ログアウト：通信が失敗しても、ログイン画面へ戻る
8. 講義の選択：サイドバーで行を押すと、その講義が選択されサイドバーが閉じる／右端に残したメイン画面を押すと、選択を変えずに閉じる／右・左へのスライドで開閉する
9. 利用状況：割合の計算（四捨五入・100% 上限・上限0以下）と、80%／100% の境界での注意文の切り替え

### 6.2 段階2
1. 講義の取得：起動直後は bootstrap の `selected` を使い、取り直さない／別の講義を選ぶと取得する／同じ講義では取得しない／
   受信中・ステップ完了の待機中の講義を選び直しても取得しない／同じ講義のまま一覧の状態が変わると取得する／404・通信エラー・その他の表示／
   会話を表示している講義で失敗しても会話が残る／401 → ログイン画面／取得するとサイドバーの行が新しくなる
2. 講義本文の自動開始：条件を満たすときに1回だけ呼ぶ／受信中・失敗の表示中・全ステップ完了後・現在のステップに発言があるときは呼ばない
3. 受信：`delta` が順に足される／`done` で発言が確定する／`error` 行と途中で終わった応答は「応答が途中で止まりました。」になり、講義を取り直す
4. 送信：空白だけでは送れない／受信中・ステップ完了の待機中・講義の取得中・読み直しの間は送れない／送信した発言がすぐ会話に出て、入力欄が空になる／全ステップ完了後も送れる
5. 受信の失敗：結果ごとのメッセージ（403 はサーバーの文言、`error` 行の `message` は出さない）／次の受信を始めるとメッセージが消える／
   途中まで届いた文字が読み直しの間も残る／読み直しが失敗しても表示が残り、途中まで届いた文字が途切れた発言になる／読み直すとサイドバーの行が新しくなる
6. 講義の切り替え：受信中に別の講義を選んでも受信が続き、届いた文字はその講義にだけ反映される／戻ると続きが表示される／
   別の講義を選んでいる間に完了を受けても次のステップの講義本文が始まる／一覧から消えた講義の受信をやめる／ログアウト・セッション切れで受信をやめる
7. ステップ完了：成功すると次のステップの講義本文が始まり、サイドバーの行が新しくなる／受信の失敗の表示中に成功すると、メッセージが消えて講義本文が始まる／
   待機中に再度押しても2回目が送られない／取得中・読み直しの間は押せない／失敗の表示と取り直し／もう一度押すとエラーメッセージが消える
8. 利用状況の更新：受信（再生成を含む）とステップ完了の成功・失敗の後に取り直す／401 では取り直さない／取り直しに失敗しても表示が残る
9. 再生成：押せる条件（最後が回答の無い質問・途切れた発言／発言の無いステップでの失敗／全ステップ完了後は質問への回答だけ）／
   `done` で隠した発言が置き換わる（ID が異なる手元の発言も含む）／取得中・読み直しの間は押せない

会話の表示（WebView）は TestStore では確かめられないため、`Docs/ADR/0003-render-conversation-with-webview-katex.md` の方法で確かめる。

1. 状態の変化から WebView へ送る内容を計算する関数が、発言の追加・受信中の発言の更新・講義の切り替え・再生成の受信中に置き換える発言を隠すこと・
   途切れた発言と回答の無い質問の文言で正しい内容を返す／発言を送ったときは、全体を描き直す場合も末尾を表示する
2. 数式を含む教材を WebView に描かせたとき、描画に失敗した数式が0個である
3. 横にスクロールする枠に触れたとき、枠を右へ戻せるかどうかを Swift へ正しく知らせる（サイドバーが開かないことは実機の操作で確かめる）

### 6.3 段階3
1. タブ：講義ごとに表示中のタブを覚える／初めて開く講義は「講義」になる／「確認テストへ」で「確認テスト」になる／タブバーを出さない講義の判定
2. 取得：4.15 の各場面で呼ぶ／テストの途中と結果の画面では呼ばない／`quizStatus` が `ready` 以外では呼ばない／結果ごとの表示／
   取得済みなら失敗しても表示が残る／次の取得でエラーメッセージが消える／401 → ログイン画面／テストを始めると取り直しをやめる
3. 開始：正答率の計算（未解答は「—」、最新の解答だけを数える）／絞り込みの和集合／出題数が0なら始められない／誤答が0問なら復習モードを始められない
4. 出題：出題順のシャッフル（乱数を固定して確かめる）／復習モードの対象／通常と復習モードの切り替え
5. 解答：選び直せる／選ぶまで回答できない／確定後は選び直せない／採点中に再度押しても2回目が送られない／結果ごとの表示／
   失敗しても選択が残る／もう一度押すとエラーメッセージが消える／解答で最新の解答が更新される／401 → ログイン画面
6. 結果：正解の数と正答率／今回の誤答の一覧／再挑戦の問数は講義全体の誤答の数／再挑戦が0問なら押せない／「講義へ戻る」の後も結果が残る
7. テストをやめる：開始画面へ戻り、取り直す／採点中はやめられない／解答済みの記録が最新の解答に残る
8. 途中経過：タブや講義を切り替えて戻ると続きになる／採点の結果はその講義にだけ届く／一覧から消えた講義の途中経過を捨てる／ログアウト・セッション切れで捨てる

確認テストの表示（WebView）は、6.2 の会話の表示と同じ方法で確かめる。

1. 状態の変化から WebView へ送る内容を計算する関数が、選択・正誤と解説・結果の一覧で正しい内容を返す
2. 数式を含む問題文・選択肢・解説を描かせたとき、描画に失敗した数式が0個である
3. 選択肢に触れたとき、選んだ選択肢を Swift へ正しく知らせる（横にスクロールする操作では選択にならないことは実機の操作で確かめる）
