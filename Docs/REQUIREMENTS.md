# AI講師 iOS 要件定義書

> 本書は iOS 版で**Web版と異なる点・追加する点だけ**を書く。共通の仕様（用語、講義の構造、
> AI の振る舞い、上限値など）は Web版の要件定義書を正とし、「Web §4.6」のように節番号で参照する。
> Web版：`https://github.com/pinshypinshy/ai-koushi` の `REQUIREMENTS.md`

---

## 1. 概要

### 1.1 目的
- AI講師の受講・確認テスト・誤答の復習を、スマートフォンのネイティブアプリで行えるようにする

### 1.2 Web版との役割分担
| 作業 | 主に使う環境 | 理由 |
|---|---|---|
| 講義の作成（教材の貼り付け） | Web版（PC） | 長い教材の貼り付けと確認は、大きな画面とキーボードが向いている |
| 受講・確認テスト・誤答の復習 | iOS版 | 短い空き時間に少しずつ進める使い方が中心になる |

### 1.3 前提
- サーバー・API・認証は Web版の本番環境をそのまま使う。iOS版のためにサーバーは変更しない
  （変更が必要になった場合は、その時点で個別に判断する）
- API の契約は Web版の `shared/api.ts` を正とする
- 用語は Web §2 に従う

## 2. スコープ

### 2.1 段階
| 段階 | 内容 |
|---|---|
| 1 | ゲストログイン＋サイドバー（講義一覧・利用状況・ログアウト）＋選択中の講義の概要 |
| 2 | 講義のストリーミング受講（講義本文・質問応答・ステップ完了） |
| 3 | 確認テスト・誤答の復習 |
| 4 | 設計判断の記録（ADR）の整備 |
| 5 | Googleログイン、講義作成、App Store 公開（実施するかは未定） |

### 2.2 段階1の範囲
**含む**：ゲストログイン、サイドバー（講義一覧・利用状況・ログアウト）、選択中の講義の概要、
空状態、セッション切れの扱い

**含まない**：
- Googleログイン（サーバー側の変更が必要になる見込みのため。段階5）
- 受講（メイン画面に講義本文を出すのは段階2）
- 講義の作成・削除・複製・名前の変更（Web版で行う）

### 2.3 段階2の範囲
**含む**：選択した講義の取得、講義本文の受信（③）、質問・応答（④）、ステップ完了（⑤）、進捗パネル、
全ステップ完了後の質問、Markdown・数式の表示、受信の失敗と中止の扱い、利用状況の更新

**含まない**：
- 確認テストと、確認テストへの導線（段階3）
- 教材の閲覧（Web §4.4 の教材タブ。iOS版では作らない）
- 完了済みのステップを押して、その時点の対話ログを読む操作（Web §4.2.3。会話は1本の時系列ですべて読めるため）

## 3. 画面

画面の骨格は「メイン画面＋左から開くサイドバー」とする。講義一覧はサイドバーに置き、
メイン画面にはサイドバーで選んだ講義を表示する（Web §3.4 のサイドバーと同じ構成）。
サイドバーはメイン画面の背面に置き、開くときはメイン画面を右へずらしてサイドバーを見せる
（X や Claude の iOS アプリと同じ形）。

| ID | 画面 | 表示する条件 |
|---|---|---|
| iSC-01 | ログイン | 起動時に未ログイン／セッション切れ／ログアウト後 |
| iSC-02 | 選択中の講義 | ログイン済みで講義が1件以上 |
| iSC-03 | 空状態 | ログイン済みで講義が0件 |
| iA-1 | サイドバー | iSC-02・iSC-03 の左上のメニューボタン、またはメイン画面を右へスライドして開く |

### 3.1 iSC-01 ログイン
- ログインID・パスワードの入力欄と、ログインボタン
- パスワードは伏せ字で表示する
- エラーメッセージの表示領域
- ログインIDの欄で改行キーを押すとパスワードの欄へ移り、パスワードの欄で改行キーを押すとログインボタンを押したのと同じ動きになる
- 入力欄は iOS のパスワード自動入力に対応させる。ログインIDの欄では自動の大文字化と修正候補を切る
- 送信中は、ログインボタンの中に読み込み中の表示を出す

### 3.2 iSC-02 選択中の講義
- 一番上の行に、サイドバーを開くメニューボタンと、選択中の講義のタイトル（1行に収まらなければ末尾を省く）を置く
- 講義の状態（`status`）が `ready` 以外のときは、状態だけを表示する。表示は 3.4 の講義一覧の行と同じ
- `ready` のときは、上から次を置く

1. **進捗パネル**（Web §4.2.3 の C-1 をモバイル向けにしたもの。Web SC-M01・SC-M02）
   - 折りたたんだ状態では1行で「ステップ n / 全体の数・現在のステップのタイトル」を表示する。
     全ステップ完了後は「全ステップ完了」と表示する
   - 押すと全ステップの一覧を展開する。完了したステップはチェックの印、現在のステップは強調、
     未着手のステップは淡い色で表示し、「k / 全体の数 ステップ完了」を添える。もう一度押すと閉じる
   - ステップのタイトルは文字のまま表示する（数式として組まない。Web版の区切りの表示と同じ）
2. **会話**（WebView で表示する。`Docs/ADR/0003-render-conversation-with-webview-katex.md`）
   - 発言を時系列に並べる。AI の発言は左寄せで Markdown・数式として表示し、利用者の発言は右寄せで文字のまま表示する
   - 各ステップの最初の発言の前に、「ステップ n・タイトル」の区切りを入れる
   - Markdown と数式の規則は Web §4.1.3 と同じ。文中の分数は独立した行の数式と同じ大きさで組む（`\frac` を `\dfrac` として扱う）。
     生の HTML は HTML として扱わず、文字のまま表示する
   - 画像は外部から読み込まず、代わりの文字（画像の説明）を表示する（アプリが利用者の操作なしに通信しないようにするため）
   - 画面幅に収まらない数式・表・コードブロックは、それぞれの枠の中で横にスクロールさせ、会話全体は横にスクロールさせない
   - 受信中の発言は、届いた文字から順に表示する。まだ1文字も届いていなければ「応答を待っています」と表示する
   - 講義を開いたとき、利用者が発言を送ったときは末尾を表示する。新しい文字が届いたときは、末尾を表示している場合だけ末尾へ追従する
     （上へ戻って読んでいる最中に引き戻さないため）
   - リンクを押すと、利用者が既定に設定しているブラウザで開く。`http`・`https` 以外のリンクは、押しても何もしない
3. **操作の領域**（会話と入力欄の間）。次のうち、条件に合うものを1つ表示する
   - 受信に失敗したとき：エラーメッセージ（4.9）と「続きを生成する」ボタン。全ステップ完了後は、ボタンを出さずエラーメッセージだけを出す
   - 全ステップ完了後：「全ステップが完了しました」と「まだわからないことがあれば、いつでも質問してください」
   - 受信中でなく、現在のステップに発言が1件以上あるとき：「次のステップへ進む」ボタン（最後のステップでは「講義を終える」）。
     ステップの完了を待つ間は「要約を作成しています」と表示して押せなくする。失敗したときはボタンの下にエラーメッセージを出す（4.11）
4. **入力欄**（画面の下端。キーボードが出ている間はキーボードの上）
   - 複数行の入力欄と送信ボタンを置く。改行キーは改行を入れる（日本語の変換の確定と区別できないため、送信は送信ボタンだけで行う）
   - 前後の空白を除いて空のとき、受信中、ステップの完了を待つ間は、送信ボタンを押せない

### 3.3 iSC-03 空状態
- 左上にサイドバーを開くメニューボタンを置く
- 講義がまだ無いことと、講義は Web版で作成することを案内する
  - 見出し：「まだ講義がありません」（Web SC-02 と同じ）
  - 説明：「講義は Web版で作成できます。作成した講義は、サイドバーの一覧を下に引っ張ると表示されます。」
- 「Web版を開く」ボタン（利用者が既定に設定しているブラウザで本番の URL を開く）

### 3.4 iA-1 サイドバー
開閉は次のとおり。どの操作でも、メイン画面が動くアニメーションで開き、閉じる。

- メイン画面のどこからでも右へスライドすると、指に合わせてメイン画面がずれ、サイドバーが見えてくる
- 開いている間は、右端にメイン画面の一部を残し、角を丸める。メイン画面は暗くしない
- 開いている間に左へスライドすると、指に合わせて閉じていく
- 指を離したとき、一定以上の速さで払っていれば払った向きに従う。そうでなければ、半分以上ずれていれば開き、
  そうでなければ閉じる。どちらも素早く収める
- 右端に残したメイン画面を押すと、選択を変えずに閉じる
- 開閉が確定したら、軽い振動を返す

上から順に次を置く。

1. **見出し**：「AI講師」（スクロールせず、常に一番上に表示する）
2. **講義一覧**（`CourseSummary` の項目）

   | 講義の状態（`status`） | 表示 |
   |---|---|
   | `ready` | タイトル、進捗（`completedSteps` / `totalSteps`）。`totalSteps` が 0 のときは進捗を出さない |
   | `generating` | タイトル、「生成中」 |
   | `failed` | タイトル、「生成に失敗しました」 |

   - 並び順はサーバーが返した順のまま（並べ替えない）
   - 行と行の間に区切り線を出さない。選択中の講義の行は、角を丸めた背景で強調する
   - 行を押すと、その講義を選択状態にしてサイドバーを閉じる
   - 下に引っ張ると一覧を取り直す（4.3）
   - 講義が0件のときは、一覧の代わりに「講義はまだありません」と表示する
3. **今月の利用状況**（`UsageSummary`。Web §3.4 A-5 と同じ表示）
   - 「AI利用額」：`costUsd / costLimitUsd` を割合（%）で示す帯。金額は表示しない
   - 「講義作成」：`courses / courseLimit` を「n / 上限 件」と帯で示す
   - 割合は四捨五入した整数で、100% を上限とする。上限が0以下のときは 0% とする
   - 2本のうち大きい方の割合が 80% 以上で「上限に近づいています。」、100% で
     「上限に達しました。新しい講義は作成できません。」を表示する（Web §8.2.4）
   - 帯の色は、それぞれの帯の割合で 80% 以上・100% の境界で切り替える
4. **ユーザー**（サイドバーの最下部。Web SC-15 と同じ）
   - 人のアイコンと表示名（`ApiUser.displayName`）を並べたボタンを置く
   - 押すとメニューを開き、表示名・メールアドレス（`ApiUser.email`）と「ログアウト」を出す。
     「ログアウト」を押すと 4.5 を行う

## 4. 振る舞い

### 4.1 起動
1. `GET /api/bootstrap` を呼ぶ
2. 結果に応じて分岐する

| 結果 | 遷移 |
|---|---|
| 200 | 講義が1件以上なら iSC-02、0件なら iSC-03 |
| 401 | iSC-01（案内文は出さない。初めての起動やログアウト後と、期限切れを区別できないため） |
| 通信エラー | 見出し「読み込めませんでした」、説明「通信できませんでした。ネットワーク接続を確認してください。」、「再試行」ボタンを表示する |
| その他 | 見出し「読み込めませんでした」、説明「時間をおいて再度お試しください。」、「再試行」ボタンを表示する |

**満たす条件**
- 前回ログインしたまま（Cookie の有効期限内）であれば、ログイン画面を経由せずにメイン画面が出る
- 読み込み中であることが分かる
- 起動直後に選択する講義は、一覧の先頭の講義とする

### 4.2 ゲストログイン（Web §4.6）
1. ログインIDとパスワードが両方入力されるまで、ログインボタンを押せない
2. `POST /auth/guest` に `{ loginId, password }` を送る
3. 結果に応じて分岐する

| 結果 | 振る舞い |
|---|---|
| 204 | `GET /api/bootstrap` を呼び、4.1 と同じく分岐する（200 ならメイン画面、401 なら iSC-01 を出し直し、それ以外は 4.1 のエラー表示） |
| 400／401／429 | 応答の `message` をそのまま表示する。ログイン画面に留まる |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」を表示する |
| その他 | 「ログインできませんでした。時間をおいて再度お試しください。」を表示する |

**満たす条件**
- 送信中はボタンを押せない（二重送信しない）
- 失敗した後もログインIDは消えない。パスワードは空にする
- 前回のエラーメッセージ（4.4 のセッション切れの案内を含む）は、ログインボタンを押した時点で消す
- 本文の無い 400／401／429 は、表示する文言が無いため「その他」として扱う
- 401 と 429 の文言はサーバーが決める。iOS側で「IDが存在しない」と「パスワードが違う」を
  区別して表示しない（Web §4.6 の総当たり対策と揃える）

### 4.3 講義一覧の取り直し
- サイドバーの一覧を下に引っ張ったとき、`GET /api/bootstrap` を呼んで一覧と利用状況を置き換える
- 取り直した一覧に選択中の講義があれば選択を保つ。無ければ先頭の講義を選択する。
  0件になったら iSC-03 にする
- 失敗したときは、表示中の一覧を残したまま、一覧の一番上にエラーメッセージを出す。
  次に取り直しを始めた時点で消す

| 結果 | 振る舞い |
|---|---|
| 401 | 4.4 |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」を表示する |
| その他 | 「講義一覧を更新できませんでした。時間をおいて再度お試しください。」を表示する |

### 4.4 セッション切れ
- メイン画面を表示した後に API で 401 を受けたら、表示中の状態を破棄して iSC-01 へ戻す
  （4.1 の起動時と、4.2 のログイン直後の bootstrap は除く）
- iSC-01 に「ログインの有効期限が切れました。もう一度ログインしてください。」を表示する

### 4.5 ログアウト
1. `POST /auth/logout` を呼ぶ
2. 成否にかかわらず、手元の Cookie を削除し、表示中の状態を破棄して iSC-01 へ戻す
   （通信に失敗しても、利用者から見てログアウトできないことは避けるため）
- 応答を待つ間は「ログアウトしています」と読み込み中の表示を出す。先に iSC-01 へ戻すと、
  待っている間にログインし直したときの Cookie まで削除されるため

### 4.6 講義の取得
- 起動直後の講義は、`GET /api/bootstrap` の `selected` をそのまま使う（取り直さない）
- サイドバーで講義を選んだとき、および 4.3 の取り直しで選択中の講義が変わったときは、`GET /api/courses/:id` で取得する。
  同じ講義を選び直したときは取得しない
- 取得中は、iSC-02 の一番上の行の下に読み込み中の表示を出す

| 結果 | 振る舞い |
|---|---|
| 200 | 3.2 のとおり表示する。条件を満たせば 4.7 を始める |
| 401 | 4.4 |
| 404 | 「講義が見つかりませんでした。サイドバーの一覧を下に引っ張って更新してください。」を表示する |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」と「再試行」ボタンを表示する |
| その他 | 「講義を読み込めませんでした。時間をおいて再度お試しください。」と「再試行」ボタンを表示する |

### 4.7 講義本文の受信（③、Web §4.2.2）
1. 次のすべてを満たすとき、`POST /api/courses/:id/lecture` を自動で呼ぶ
   - 講義の状態が `ready` で、全ステップが完了していない
   - 現在のステップに発言が1件も無い
   - 受信中でなく、受信の失敗（4.9）を表示していない
2. 応答は NDJSON で届く（`LectureStreamLine`）。`delta` は届いた順に受信中の発言へ足し、`done` で受け取った発言を会話に確定する
3. 確定したら 4.12 を行う

**満たす条件**
- 同じステップに対して、自動では1回しか呼ばない（呼ぶたびに AI の料金がかかるため）
- 「続きを生成する」を押したときも、この手順で呼ぶ

### 4.8 質問・応答の送信（④、Web §4.2.4）
1. 送信ボタンを押すと、入力した文を会話にすぐ表示し、入力欄を空にする
2. `POST /api/courses/:id/messages` に `{ text }`（前後の空白を除いたもの）を送る
3. 応答の受け取りは 4.7 の 2・3 と同じ

**満たす条件**
- 全ステップ完了後も送信できる（Web §4.2.4、Q-32）
- 会話にすぐ表示した発言は、講義を取り直した時点でサーバーが保存したものに置き換わる

### 4.9 受信の失敗
| 結果 | 表示するメッセージ |
|---|---|
| 401 | 4.4 |
| 403 | 応答の `message` をそのまま表示する（この講義の生成量の上限に達した場合） |
| 通信エラー（応答が15秒途切れた場合を含む） | 「通信できませんでした。ネットワーク接続を確認してください。」 |
| `error` 行を受け取った／`done` を受け取る前に応答が終わった | 「応答が途中で止まりました。」 |
| その他 | 「応答を取得できませんでした。時間をおいて再度お試しください。」 |

- 401 以外では、失敗した後に `GET /api/courses/:id` で講義を取り直して会話を置き換え、4.12 を行う。
  途中まで生成された発言と送信した発言は、サーバーが保存している場合があるため（Web §5.7）
- `error` 行の `message` は表示しない（サーバー内部のエラー文であり、利用者向けの文言ではないため）
- エラーメッセージは、次に受信を始めた時点で消す

### 4.10 受信の中止
- 受信中に別の講義を選んだとき、ログアウトしたとき、セッションが切れたときは、受信をやめる
- やめた後に届いた文字は、どの講義にも反映しない

### 4.11 ステップ完了（⑤、Web §4.2.2）
1. 「次のステップへ進む」（最後のステップでは「講義を終える」）を押すと、
   `POST /api/courses/:id/steps/:stepId/complete` を呼ぶ
2. 200 で返った講義に置き換える。次のステップがあれば 4.7 が始まる
3. 4.12 を行う

| 結果 | 振る舞い |
|---|---|
| 200 | 上の 2・3 |
| 401 | 4.4 |
| 通信エラー | 「通信できませんでした。ネットワーク接続を確認してください。」を表示する |
| その他（409 を含む） | 「ステップを完了できませんでした。時間をおいて再度お試しください。」を表示し、講義を取り直す |

**満たす条件**
- 完了を待つ間はボタンを押せない（二重送信しない）

### 4.12 利用状況の更新
- 講義本文・質問応答の受信が終わったとき（成功・失敗とも）と、ステップ完了の応答を受けたときに、
  `GET /api/usage` を呼んでサイドバーの利用状況を置き換える（AI の料金は失敗しても発生するため）
- 401 なら 4.4。それ以外の失敗では、表示中の利用状況をそのまま残し、メッセージは出さない

## 6. テストの観点
TestStore で次を確かめる。API は Dependency を差し替え、本物を呼ばない。

### 6.1 段階1

1. 起動：200（講義あり）→ 選択中の講義（先頭）／200（0件）→ 空状態／401 → ログイン画面／通信エラー → エラー表示
2. ログイン：204 → メイン画面へ／401・429 → サーバーの文言を表示し、パスワードが空になる／通信エラー → 規定の文言を表示
3. ログイン：送信中に再度ボタンを押しても、2回目の送信が起きない
4. 取り直し：失敗しても表示中の一覧が残り、エラーメッセージが出る／次に取り直しを始めるとエラーメッセージが消える／選択中の講義が残っていれば選択を保つ
5. セッション切れ：401 を受けたらログイン画面へ戻り、案内文が出る
6. ログアウト：通信が失敗しても、ログイン画面へ戻る
7. 講義の選択：サイドバーで行を押すと、その講義が選択されサイドバーが閉じる／右端に残したメイン画面を押すと、選択を変えずに閉じる／右・左へのスライドで開閉する
8. 利用状況：割合の計算（四捨五入・100% 上限・上限0以下）と、80%／100% の境界での注意文の切り替え

### 6.2 段階2
1. 講義の取得：起動直後は bootstrap の `selected` を使い、取り直さない／別の講義を選ぶと取得する／同じ講義では取得しない／404・通信エラー・その他の表示／401 → ログイン画面
2. 講義本文の自動開始：条件を満たすときに1回だけ呼ぶ／受信中・失敗の表示中・全ステップ完了後・現在のステップに発言があるときは呼ばない
3. 受信：`delta` が順に足される／`done` で発言が確定する／`error` 行と途中で終わった応答は「応答が途中で止まりました。」になり、講義を取り直す
4. 送信：空白だけでは送れない／受信中とステップ完了の待機中は送れない／送信した発言がすぐ会話に出て、入力欄が空になる／全ステップ完了後も送れる
5. 受信の失敗：結果ごとのメッセージ（403 はサーバーの文言、`error` 行の `message` は出さない）／次の受信を始めるとメッセージが消える
6. 受信の中止：受信中に別の講義を選ぶと受信をやめ、その後に届いた文字が反映されない
7. ステップ完了：成功すると次のステップの講義本文が始まる／待機中に再度押しても2回目が送られない／失敗の表示と取り直し
8. 利用状況の更新：受信の成功・失敗とステップ完了の後に取り直す／失敗しても表示が残る

会話の表示（WebView）は TestStore では確かめられないため、`Docs/ADR/0003-render-conversation-with-webview-katex.md` の方法で確かめる。

1. 状態の変化から WebView へ送る内容を計算する関数が、発言の追加・受信中の発言の更新・講義の切り替えで正しい内容を返す
2. 数式を含む教材を WebView に描かせたとき、描画に失敗した数式が0個である

## 7. 決定事項

| 決定 | 理由 | 記録 |
|---|---|---|
| アーキテクチャは TCA | ストリーミングの状態遷移・途中キャンセル・遅れて届いたデータの扱いを、仕組みとして持てるため | `Docs/ADR/0001-adopt-tca.md` |
| ローカルパッケージでモジュールを分割する | 依存の向きをコンパイラに守らせるため | `Docs/ADR/0002-modularize-with-local-package.md` |
| Web版とは別リポジトリ | リリースの単位（App Store の審査／Cloudflare へのデプロイ）と開発ツールが異なるため | — |
| 段階1の認証はゲストログインのみ | 既存の Cookie によるセッションを、サーバーを変えずにそのまま使えるため | — |
| 講義一覧はサイドバーに置き、メイン画面には選択中の講義を表示する | Web版と同じ構成にし、起動してすぐ前回の講義に戻れるようにするため | — |
| 講義の会話は1つの WKWebView で表示し、Markdown と数式は Web版と同じ処理（KaTeX）で描く | 数式を確実に正しく表示し、かつ誤りを検知しやすい設計にするため | `Docs/ADR/0003-render-conversation-with-webview-katex.md` |
