# 受講と確認テストの状態を、講義1つ分の親にまとめる

## ステータス

承認

## コンテキスト

- 確認テストの途中経過を講義ごとに残す（`Docs/REQUIREMENTS.md` §4.18）。受講の状態は、すでに講義ごとに持っている（ADR 0004）
- 受講の状態と確認テストの状態は、作るときも捨てるときも同じ講義の単位で揃える必要がある
- Web版は確認テストの途中経過をアプリ全体で1つだけ持ち、講義やタブを切り替えると空にする

## 決定

- `CourseItemFeature` が講義1つ分の `lecture`・`quiz`・`selectedTab` を持ち、`CourseFeature` はこの一覧を持つ
- `QuizFeature` は `CourseFeature` モジュールに置く
- 途中経過は端末に保存しない
- ADR 0004 の決定（講義ごとに状態を持ち、切り替えても受信を続ける）は変えない。その一覧の要素に親を挟む

## 検討した他の案

### `lectures` と `quizzes` の一覧を2本持つ

- 利点：既存のコードの変更が少ない
- 採らなかった理由：作成と削除を手で揃えることになり、忘れても見つからない

### `LectureFeature` の子にする

- 利点：変更が最も少ない
- 採らなかった理由：名前と責務が合わなくなる

### 途中経過を端末に保存する

- 利点：アプリが終了しても続きから再開できる
- 採らなかった理由：保存用の Dependency、形式の変更への対応、ログアウト時の削除が必要になる

## 結果（受け入れたコストを含む）

- 受講と確認テストの状態を、片方だけ作り忘れたり消し忘れたりしない
- `.lectures(...)` の経路が変わり、`CourseFeature` のテストを書き換える必要がある
- アプリが終了すると途中経過は消え、未解答の問題だけを続ける手段は無い
